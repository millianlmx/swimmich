# UI scenarios run by Scripts/ci.sh beside the unit tests, one xcodebuild run per
# line, each on a simulator of the pool reset for it (`--erase`: freshly erased)
# and against its own stub (UITests/stubs/<stub.py>, on the worker's port):
#
#   <stub.py> <Class>[/<test>] [--content-size <simctl category>]
#             [--media <file name>]... [--skip <test>]... [--erase]
#             [--smoke | --release]
#
# A test that fails or skips itself fails the CI. Scenarios not listed here are
# compiled by the CI, not run. The lines run several at a time and a free
# simulator takes the next one: one test per line, the longest first. The run
# lasts at least as long as its longest line: a test over 3 minutes gets a CI
# warning and is cut in several.
#
# Where a criterion is proven, from the cheapest up:
#
# 1. a unit test (a view model, a request, a mapping, a label): milliseconds;
# 2. a hosted screen (Tests/HostedScreen.swift: the real view on a mock client,
#    read through its accessibility tree at any text size and language): a
#    second for a whole screen, where a scenario takes minutes;
# 3. a scenario of this list, for what only a launched app shows: a journey
#    across screens, another process (share extension, widgets, Photos, the
#    provider's sign-in page), the system (Face ID, SpringBoard), a relaunch.
#
# A line has a tier, which says when it runs (Scripts/ci_ui_select.py):
#
# * `--smoke`: every push (the gate), after the lines the push changed. One per
#   critical journey, each under two minutes: timeline and viewer, search,
#   editor. The gate has five minutes in all (`SWIMMICH_CI_GATE_BUDGET`), on a
#   runner with two simulators: the sign-in walk (three minutes) is a core line.
# * no flag, the core suite: every night with the smoke lines. A journey of a
#   feature, or the only execution proof of a criterion (no unit test proves it).
# * `--release`: once a week and on a release tag, with all the others. A second
#   proof of a criterion a unit test of the same name already proves.
#
# Budgets, checked by the CI: at most 5 smoke lines, at most 30 lines in the
# night's suite (smoke and core). A feature brings one or two scenarios; one that
# does not fit replaces a line or is `--release`, and its detailed criteria go to
# the unit tests.
